# 特徴量の選択・設計

現行の特徴量を維持するか、どの特徴量集合・生成方法へ変更するかを判断する。
依頼整理・run・履歴・総評は `analyze` に従い、このSkillの比較方法と終了条件を適用する。
パラメータだけの変更は `parameter-tuning`、予測の誤差診断は `error-analysis` を使う。

## 入力と判断基準

既存の依頼・コード・結果から次を揃え、判断に必要な未決事項を確認する。

- 基準モデル、現行特徴量の定義・生成コード、予測時点と入力の利用可能時点。
- 開発データの版・対象・分割規則と、最終ホールドアウトの範囲・利用履歴。
- 削減・追加・変換の範囲、固定パラメータと再調整の可否、候補数や時間の上限。
- 主指標、削減時の許容性能低下、追加時に必要な改善幅、同点の扱い、選定の委任範囲。

基本は同じ検証条件での性能とモデル入力列数を比べる。取得費・生成時間などは案件の制約に応じて加え、
列数から費用を推測しない。予測時に同じ定義で再現できることを候補の前提とする。
探索は開発データ内で行い、改善判断に使っていない最終ホールドアウトを分ける。
確保できなければ開発結果のみを報告する。再開時に最終評価済みなら、報告から続ける。

## 手順

1. **比較条件を揃える。** 基準と候補の評価対象・分割・指標を揃え、最初はモデル設定を固定する。
   学習を伴う補完・変換・選択は各学習部分で行う。目的変数による符号化や時系列の結合は
   [比較設計](references/comparison.md)に従い、学習行自身の正解や予測時点より後の情報を混ぜない。
2. **変更候補を作る。** 基準のtrain・valid性能、誤差、bootstrapなしのSHAPとfeature importanceを確認する。
   [重要度の読み方](references/importance.md)を使い、相関や同じ由来の特徴量も考慮する。
   削減では除外する列・群、追加・変換では表現したい情報、生成式・窓幅・利用時点を記す。
3. **再学習して比較する。** 候補の特徴量一覧・生成コードを保存し、性能差と列数の増減を測る。
   特徴量の分布や2値分類のROC・較正をPythonで描くときは、[inquiry-lab-api](../inquiry-lab-api/SKILL.md)で対応する関数を確認する。
   追加・削減は必要な順で行い、節目では当初の基準との差も確認する。
   重要度は候補発見に使い、採否は再学習後の性能で決める。
4. **次の行動を決める。** 削減は許容低下幅、追加・変換は必要改善幅と制約に照らして採用・見送り・保留を選ぶ。
   設定との相互作用やばらつきが判断を左右する場合は、比較設計の追加診断を予算内で選ぶ。
   委任されていないトレードオフは、性能差と入力・処理の負担を利用者に示す。

## 終了条件

- **開発結果で終了する：** 現行維持・候補見送りを判断した、追加試行の価値が低い、または予算に達した場合。
  ホールドアウトを使わず、判断と残る証拠不足を報告する。
- **最終評価へ進む：** 性能・特徴量数と案件の制約を満たす根拠があり、必要な利用者判断が済んだ場合。
  特徴量一覧・生成処理・前処理・モデル設定・予測閾値・再学習範囲・比較する基準と評価方法を固定する。
- **最終評価後は終了する：** 期待以下の結果も報告して閉じ、今回の探索へ戻らない。
  次の改善分析には利用履歴を引き継ぎ、新たな最終評価用の未使用データを用意する。

最終ホールドアウトの値・要約・予測・重要度は、特徴量選択・早期停止・閾値調整に使わない。

## 出力

[レポート雛形](assets/report.md)で `output.md` を作る。
執筆には[成果物の共通方針](../analyze/references/deliverables.md)を使い、次の5章で変更意図・比較結果・判断をつなぐ。

1. **結論：** 目的、特徴量集合・生成方法の変更または現行維持・保留、決め手、重要な限界を示す。
   特徴量一覧・生成コード・モデルの版を特定し、最終評価の実施・未使用・確保不能と理由を記す。期待以下の結果も含める。
2. **性能と特徴量数の比較：** 最終評価を先に示し、開発結果とは表を分ける。
   表には評価対象・構成とモデル版、主指標・単位、基準との差と改善方向、入力列数と増減、パラメータ変更、基準への適合・採否を載せる。
   許容低下幅・必要改善幅と実測差を対応づけ、列数の数え方を記す。変更を重ねた場合は当初の基準からの累積差も示す。
   費用・安定性などを評価した場合は測定条件・値・基準を添える。
3. **特徴量の変更方針と検証：** 入力・予測時点、開発／最終評価の境界・分割、基準と探索範囲・予算、判断基準と判断者、
   学習部分内の処理・利用時点・評価対象・乱数を共通条件としてまとめる。
   「重要度から見た候補」では[重要度の読み方](references/importance.md)の説明条件を記し、主要な列・群の重要度と変更仮説を表にする。
   木モデルのgain・利用回数とSHAP、符号付きSHAPの分布から選定理由を説明し、全特徴量の表・図は原本へつなぐ。
   主要な変更ごとに観測、変更した列・生成方法と意図、固定条件、再学習の結果、反証、採用・見送り・保留を対応づける。
   再調整した場合は基準と候補の探索条件を示し、固定設定での比較と分ける。
   最終評価へ進んだ根拠と固定構成・再学習手順、または開かずに終えた理由を記す。
4. **適用範囲と残る課題：** 対象・期間・入力の取得条件、未確認条件、残る選択、停止理由を示す。
   追加改善は次の分析候補とし、最終評価後は利用履歴と未使用の評価データを引き継ぐ。
5. **参考：** 依頼、作業履歴、特徴量定義、候補別結果、生成・選択・学習コードへの入口をまとめる。

各runから全特徴量の定義・依存元・利用時点、入力・コードの版、分割、設定、乱数、環境、結果を辿れるようにする。
