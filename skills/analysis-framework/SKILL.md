# 分析フレームワーク

## 1. 分析目的を受け取る

「誰が、何を判断・理解できるようにするか」を一文で捉える。方法が先に指定されている場合も、
その方法で答えたい問いを確かめる。既存分析の再開では、現在の答え、関連するrun、前回の停止理由を
確認し、新しい証拠や指示で見直す必要がある判断から再開する。

## 2. 対話で問いと判断基準を詰める

まず、依頼の目的と入力に合うテーマ別スキルが利用できるかを確認する。

- **該当するスキルがある場合**は、その適用条件を読み、今回使える用語の定義、比較方法、判断基準を対話に取り入れる。
- **該当するスキルがない場合**は、最初の試行を選ぶための情報を集める。具体的には、答えたい問い、対象と範囲、使えるデータ、何が分かれば十分か、時間や費用の制約を押さえる。

未知のテーマで得た質問や判断基準に再利用の価値がある場合は、そのテーマと適用条件を添えて
テンプレート候補にする。テンプレートの文書化は別の作業として扱い、今回の分析はそのまま進める。

調べて分かる事実は自分で確認する。利用者の判断が必要な論点は、前提が決まったものから少数ずつ、
推奨案と理由を添えて尋ねる。最初の試行の目的と範囲が定まれば進み、結果を見て決める事項は保留する。
計画だけの依頼なら、ここで問い、判断基準、試行案、未決事項を返す。

望む成果、問いに答えるために必要な証拠、停止条件を区別する。定量化できる場合は、指標、比較対象、
閾値とその理由、評価方法、不確実性を具体化する。基準の根拠が足りないときは、設定に必要な情報を示す。
判定に使う結果を見る前に基準を記録し、探索結果から基準を変更した場合は、以前の基準・変更理由・
すでに見た証拠を残す。

## 3. 分析ループを進める

1. **試行の問いを選ぶ。** 目的に照らして不足している証拠を特定し、次のrunで答える問いを一つ選ぶ。
   どんな結果なら現在の答えや行動が変わるかを示し、過去の試行との重複、実行可能性、費用を考慮する。
2. **分析を実施する。** 問いに合う方法を選び、一まとまりの試行を一つのrunとして扱う。
   予定と実施した内容を区別し、失敗した試行も理由とともに残す。
3. **結果を評価する。** 実際の出力を判断基準に照らし、支持・反証する証拠と限界を確認する。
   過去のrunとも比較し、何が観測され、何が解釈で、どこに不確実性が残るかを示す。
4. **終了を判定する。** 問いに十分答えられたか、残る制約の中で答えを変えうる追加試行があるかを判断する。
   同じ問いを続ける、手法を修正する、関連する別の問いへ分岐する、探索を止める、のいずれかを選び理由を残す。

目的・対象範囲・予算を大きく変える必要が生じたら対話に戻る。予算には評価と総評の時間も含める。
追加試行の価値が低い場合や利用可能な情報を調べ尽くした場合は、未解決の点を示して総評へ進む。

## 4. 総評を作成する

元の目的に立ち戻り、問いごとに現在の答え、判断を支える証拠、重要な留保をまとめる。
詳しい手法や試行経過は該当するrunを参照する。望んだ成果が得られなかった場合も、
証拠から答えられたことと、判断を保留したことを区別する。
停止理由と、何が得られれば再開する価値があるかを示す。

[分析レポートと作業history](references/deliverables.md)の共通構成を使う。各runの実施内容・根拠・次の判断を
historyに残し、総評では判断に必要な値や図表を本文に載せる。テーマ別スキルがあれば、その掲載項目を該当する問いに組み込む。
