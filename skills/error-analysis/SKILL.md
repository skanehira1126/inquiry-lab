# モデルの誤差分析

分類・回帰・ランキングの予測を診断し、どの条件で何が起きているかを説明する。
依頼整理・run・履歴・総評は `analyze` に従う。
このSkillは一括診断で完了し、analyzeの一般ループは重ねない。
モデルの変更・採用比較は `feature-design` または `parameter-tuning` へ渡す。

## 入力と判断基準

既存の依頼・コード・結果から次を揃え、判断に必要な未決事項を確認する。

- 予測の用途と調べたい誤り、予測・正解・照合キー、モデル版と予測の生成条件。
- 診断に使える開発データの版・対象・属性、分割と学習範囲、最終ホールドアウトの利用履歴。
- 全体と比較するセグメント、ベースライン、指標・図、少数例の扱い、件数や時間の上限。
- 許容誤差・損失などの判断基準。改善仮説の順位付けを求める場合は、その基準と判断者。

基本は開発validまたはOOF予測を使う。学習標本内の予測しかなければ、その範囲の診断として報告する。
診断・仮説作成に最終ホールドアウトを使わない。独立評価用のデータがなくても開発診断はできる。
再開時に最終評価済みなら、報告から続ける。

## 手順

1. **診断を計画する。** 用途・業務区分・既知の課題からセグメントを選び、定義と理由を記す。
   [評価方法](references/diagnostics.md)から問いに合う指標・図を選ぶ。
   事例確認や区間推定も、行う場合は対象・方法・件数を先に決める。
2. **入力を照合する。** キーの粒度・重複、結合失敗、正解の欠測・確定時点、予測範囲を確かめる。
   評価件数と除外理由を残す。モデル・前処理・予測閾値を固定し、比較対象の行と指標を揃える。
3. **一括で測定する。** 計画した全体・条件別の集計、図、事例を作る。
   2値分類のROC・較正やスコア分布をPythonで描くときは、[inquiry-lab-api](../inquiry-lab-api/SKILL.md)で対応する関数を確認する。
   各条件の件数・分母・誤差の大きさを併記し、誤りやすさと影響の量を分ける。
   入力・計算の不備は同じ計画内で修正し、測れない項目は理由と影響を残す。
4. **解釈する。** 強み・弱み・目立つ偏りなし・根拠不足を区別する。
   仮説には支持する観測と反例・代替説明を添える。順位付けが必要なら影響、根拠、検証負担で比較する。
   結果から生じた新しい切り口や改善案は、次の分析候補として返す。

## 終了条件

計画した全項目の結果と解釈、または未実施・評価不能の理由を整理し、レポートを作ったら完了する。
目立つ偏りや改善仮説がなくても終了する。予算到達や入力不足の場合は、確認範囲と未完了項目を報告する。
今回の結果から切り口を増やしたり、改善仮説の検証を始めたりしない。

診断だけなら最終ホールドアウトは未使用に保つ。
独立データで固定モデルを確認することが当初の計画に含まれ、開発診断で入力の対応と比較が成立した場合は、
必要な利用者判断を解決し、モデル・予測閾値・対象条件・指標・集計と再学習の有無・手順を固定して最終評価する。
評価後は期待以下でも報告して終了する。次の改善分析には利用履歴を引き継ぎ、最終評価用の未使用データを用意する。

## 出力

[レポート雛形](assets/report.md)で `output.md` を作る。
執筆には[成果物の共通方針](../analyze/references/deliverables.md)を使い、次の5章で全項目の結果と根拠を辿れるようにする。

1. **検証項目の報告：** 目的と対象、全体所見、停止理由と完了状況を示す。
   最終評価の実施・未使用・確保不能と理由を記し、期待以下の最終結果も全体所見に含める。
   計画した全項目を表にし、問い、対象・セグメント、指標・図、実施状況、主要値と解釈、3章へのリンクを対応づける。
   未実施・評価不能は理由と影響を添える。
2. **傾向が見つかった項目：** 特徴的な強み・弱み・偏りを件数・値・比較条件、解釈、重要な反例・限界とともに示す。
   必要な図表を載せ、3章の根拠へつなぐ。未検証の原因・改善効果は仮説とし、傾向がなければ確認範囲とその結論を示す。
3. **それぞれの検証方法と内容：** 予測の由来・版・期間・集団・学習範囲・分割、照合と除外、
   セグメント・指標・図の定義と選定理由、比較対象・単位・重み・集約、判断基準の根拠・設定時点・判断者を共通条件として記す。
   各項目に問い、方法、比較条件、結果・解釈、原本への参照を置く。分類はクラス・閾値・必要な正例負例数、
   回帰は残差の符号・単位、ランキングはクエリ・候補集合・k、特殊な評価は帯・積分範囲・分位水準などを明記する。
   結果表には対象・比較対象、件数・割合・分母、指標・誤差、定義した差・失敗率・損失寄与、判断・限界を載せる。
   最終評価は開発結果と別の表で示す。事例確認では抽出方法と失敗例・反例の正解・予測・入力を対応づける。
   修正・再計算、計画との差、計算不能は理由と影響を示す。
4. **適用範囲と次の検証：** 適用できる範囲、未確認条件、残る判断を示す。
   次の候補があれば問い、変更案、固定する比較条件、使える開発データ、判断指標、支持・反証の条件を記す。
   順位付けを依頼された場合は影響・根拠・検証負担を対応づける。候補がなくても完了できる。
5. **参考：** 依頼、作業履歴、予測・集計・図・事例の原本、生成・評価コードへの入口をまとめる。

各runに入力・モデル・コードの版、分割、照合・除外規則、指標・重み、抽出条件・乱数、環境、成果物を残す。
