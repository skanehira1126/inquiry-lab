# 誤差診断の評価方法

診断計画を作るときに、問いに合う方法を選ぶ。全項目の実施は求めない。
指標の定義・方向・重み・集約単位と、少数例や計算不能の扱いを揃える。
計算不能はN/Aと理由・件数を示す。

## 分類

| 確かめること | 方法 | 揃える条件 |
|---|---|---|
| 見逃し・誤検知と運用負担 | 混同行列、再現率、適合率、誤検知件数 | 正例・クラス順、閾値、割合の分母 |
| スコアの順位付け | 全体・セグメント別ROC AUC | スコアの向き、正例・負例数、多クラスのOvR／OvO・平均方法 |
| 正例を上位に集める力 | PR曲線、Average Precision（AP） | 正例率、評価対象、集約方法。APとPR曲線の台形面積を区別する |
| 特定の運用範囲での識別性能 | スコア帯別AUC、またはpartial AUC | 前者は抽出対象、後者はROC曲線の積分区間・標準化方法 |
| 確率と実際の発生率の対応 | キャリブレーション曲線。補助にLog Loss・Brier score | クラス、ビン境界、平均予測確率・正例率・件数 |

セグメント別AUCはその集団内の識別性能であり、全体AUCの分解ではない。
正例・負例の片方がない集団はN/Aとし、少数例は定めた基準に従って解釈する。
ラベルしかない場合は、スコアや確率を要する診断を実施できない。

スコア帯別AUCでモデルを比較するときは、例えば基準モデルのスコア帯で共通対象を固定する。
各モデル自身の帯で抽出すれば対象構成も変わる。partial AUCは行の抽出ではなくROCの範囲を限定する。
境界は用途から決め、帯内のAUCを全体の性能へ一般化しない。

確率の診断は業務で使う範囲を重視し、順位付けの良さと分けて読む。
Log LossやBrier scoreだけで較正の良否を決めず、確率帯別の対応を確認する。
確率の補正学習は次の改善分析とする。

定義・実装の参照：[ROC AUC](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html)、
[AP](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)、
[キャリブレーション](https://scikit-learn.org/stable/modules/calibration.html)。

## 回帰

| 確かめること | 方法 | 揃える条件 |
|---|---|---|
| 過大・過小予測 | 残差の平均・分布、予測値や時期との残差図 | 残差は予測−正解、尺度と単位 |
| 通常の誤差と大外れ | MAE、RMSE、絶対誤差の上位分位点、許容誤差の超過率 | 分位点、許容幅、対象・重み |
| 予測の集中・裾・値域 | 予測値と正解の分布、実測値対予測値の散布図 | 同じ行・単位・ビン、予測する量が平均・中央値などのどれか |
| 相対的な誤差 | MAPEなど | ゼロ付近の正解の件数・扱い。単位付き誤差も残す |
| 過大・過小の異なる影響 | 業務損失、分位点予測ならpinball loss | 費用の根拠、分位水準 |
| 予測区間の妥当性 | 被覆率、幅、下限割れ・上限超過率 | 名目被覆率、上下限の生成方法、条件別件数 |

用途が元の単位での判断なら、その尺度で評価する。期間や複数予測先をまとめる場合は、
集計してから誤差を計算するか、各誤差を集約するかを固定する。
点予測の分布は目的変数の観測分布そのものではない。広がりの違いは行ごとの残差と合わせて読み、
分布の一致を精度の代わりにしない。

MAPEのゼロ付近の扱い、正解が一定の集団に対するR²などは実装の定義を確認する。
区間は被覆率と幅を併せて判断し、点予測のみのモデルへ追加学習を要求しない。

定義・実装の参照：[回帰指標](https://scikit-learn.org/stable/modules/model_evaluation.html#regression-metrics)、
[pinball loss](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_pinball_loss.html)。

## ランキング

| 確かめること | 方法 | 揃える条件 |
|---|---|---|
| 上位の並びの良さ | NDCG@k | 関連度、gain・順位割引、k |
| 上位の適切さ・回収率 | Precision@k、Recall@k | 関連の定義、分母、k未満の候補数の扱い |
| 最初の正解への到達 | MRRまたはMRR@k | 打切り順位、正解なしの扱い |
| 複数の関連候補の順位 | MAPまたはMAP@k | クエリごとのAP、正規化とクエリ間の重み |

同じクエリ・候補集合・関連度・k・同点処理で比較し、クエリごとの差を集約する。
MRRは最初の関連候補だけを評価する。MAPはクエリごとのAPの平均で、分類の全行をまとめたAPとは単位が異なる。
gainやAP@kの正規化などは実装で定義が異なるため、指標名だけで比較条件を揃えたとしない。

候補生成が変わる場合は、共通候補での順位と、候補生成を含む結果を分ける。
Recallの分母の範囲、関連候補なし・候補不足・未判定の扱いを記す。
候補を一部だけ抜いて順位を付け直した結果は、元の候補集合とは別の評価とする。

定義・実装の参照：[ランキング指標](https://www.tensorflow.org/ranking/api_docs/python/tfr/keras/metrics)。

## 件数・事例・不確実性

各条件に評価件数・全体比・独立対象数・必要な分母と誤差を並べる。
失敗を定義した場合は件数・率も示す。全体損失への寄与は加算できる量で計算し、
AUCなどのスコアや重複する集団を足し合わせない。条件間の差は、正解分布や対象構成の違いも含めて解釈する。

事例確認では、計画した抽出方法・件数で失敗例と同条件の成功例・反例を比較する。
正解・予測・誤差と、予測時に得られた入力を対応づける。結果確定後の情報を使った場合は区別する。
意図的に選んだ例から発生頻度を推定せず、観測した損失と改善可能な量を分ける。

SHAP・重要度は入力の使われ方を知る必要がある場合に計画し、原因や改善効果の確定には使わない。
区間推定を計画した場合は[評価の不確実性](../../parameter-tuning/references/evaluation-uncertainty.md)を参照する。
抽出単位は対象間の依存に合わせ、評価標本のぶれと再学習・選択のばらつきを区別する。
