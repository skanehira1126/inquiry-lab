# パラメータチューニング

基準設定を維持するか、どの設定へ変更するかを判断する。
依頼整理・run・履歴・総評は `analyze` に従い、このSkillの比較方法と終了条件を適用する。
特徴量の追加・削減・変換が主目的なら `feature-design` を使う。

## 入力と判断基準

既存の依頼・コード・結果から次を揃え、判断に必要な未決事項を確認する。

- 学習・予測手順と基準パラメータ、変更する設定と固定条件。
- 開発データの版・対象・分割規則と、最終ホールドアウトの範囲・利用履歴。
- 主指標の定義・方向・集約方法、必要な改善幅、副指標や費用の制約。
- 探索方法・パラメータ範囲・候補値・乱数、試行数や時間の上限、選定の委任範囲。

探索は開発データ内で行う。最終ホールドアウトは改善判断に使っていないデータを確保し、
候補を固定するまで値・要約・予測結果を探索に使わない。確保できない場合は開発結果のみを報告する。
再開時に最終評価済みなら、報告から続ける。

## 手順

1. **比較条件を揃える。** [評価設計](references/evaluation.md)から用途に合う分割と指標を選ぶ。
   基準と候補には同じ評価対象・分割・集約方法を使い、前処理は各学習部分で学習する。
2. **基準を診断する。** train・validの性能と符号付き差を確認する。
   [評価の不確実性](references/evaluation-uncertainty.md)に従い、bootstrap指標分布の幅とKS統計量Dを併記する。
   用途に必要な性能と、学習時からの低下を分けて捉える。算出が難しい項目は理由を残す。
3. **候補を比較する。** 診断から変更意図を定め、計画した候補を学習・評価する。
   2値分類のROC・較正やスコア分布をPythonで描くときは、[inquiry-lab-api](../inquiry-lab-api/SKILL.md)で対応する関数を確認する。
   設定、主指標と基準との差、副指標、費用、失敗を保存する。探索範囲を変えたら根拠となるrunを記す。
4. **次の行動を決める。** 改善幅と制約に照らして候補・現行維持・保留を選ぶ。
   追加試行で判断が変わりそうなら予算内で続ける。委任されていないトレードオフは、差と代償を利用者に示す。

## 終了条件

- **開発結果で終了する：** 現行維持・候補見送りを判断した、根拠が不足したまま追加試行の価値が低くなった、
  または予算に達した場合。ホールドアウトは未使用のまま、理由と残る問いを報告する。
- **最終評価へ進む：** 開発結果が選定基準を満たし、必要な利用者判断が済んだ場合。
  候補と比較する基準、前処理、パラメータ、予測閾値、再学習範囲、指標・集計方法を固定する。
  独立した評価標本では主指標と対応する指標差のbootstrap区間を求める。
- **最終評価後は終了する：** 期待以下の結果も報告して閉じ、今回の探索へ戻らない。
  次の改善分析には利用履歴を引き継ぎ、新たな最終評価用の未使用データを用意する。

最終ホールドアウトは候補選択・早期停止・閾値調整に使わない。

## 出力

[レポート雛形](assets/report.md)で `output.md` を作る。
執筆には[成果物の共通方針](../analyze/references/deliverables.md)を使い、次の5章で変更意図・比較結果・判断をつなぐ。

1. **結論：** 目的、推奨設定・現行維持・保留、決め手、重要な留保を示し、性能と選定理由へリンクする。
   最終評価の結果と採用判断は区別する。モデル・前処理・パラメータの版を特定し、主要な変更値は本文、全設定は原本へ置く。
2. **モデルの性能と診断：** 用途に必要な性能水準と学習時からの低下を分けて説明する。
   最終評価を実施した場合は先に示し、未実施ならホールドアウト未使用・確保不能と理由を記す。
   性能表にはモデル版、分割の役割と対象、指標・単位、点推定・区間とその算出対象、事前基準との関係を載せる。
   手順2のtrain・valid診断と用途への懸念を示す。最終評価の診断は事前指定した範囲に限り、
   再学習でモデルや分割の役割が変わった結果は分ける。算出不能は理由を添え、評価条件へリンクする。
3. **調整方針と検証：** 入力・期間・集団、開発／最終評価の境界と分割理由、基準設定、探索方法・範囲・選定理由・予算、
   判断基準と判断者、前処理の学習範囲・乱数・区間の算出対象を共通条件としてまとめる。
   小節は主要な調整方針ごとに作り、当時の観測・変更意図・選んだ設定と理由・固定条件・検証・判断をつなぐ。
   同じ方針を確かめた複数runは統合する。比較表には設定・モデル版、同条件の主指標と基準との差、副指標・費用、選定基準への適合を載せる。
   当時の動機が記録されていなければ不足とし、後の結果で補わない。条件・基準の変更は理由、既に見た証拠、比較への影響を残す。
   最終評価へ進んだ根拠と固定したモデル・評価方法、または評価せず終了した理由から2章へつなぐ。
4. **適用範囲と残る課題：** 確認済み・未確認の利用条件、証拠不足、利用者に残る判断と結論の見直し条件を示す。
   最終評価済みなら今回の探索を終了したことを記し、追加改善は今後の分析として扱う。
5. **参考：** 作業履歴、全候補の結果、評価方法・指標の定義への入口をまとめる。

各runから入力・コードの版、設定、分割、乱数、環境、全候補の結果と成果物を辿れるようにする。
探索ツールのtrialは原本に保存し、runは問いと判断のまとまりで記録する。
