# パラメータチューニング

基準設定を維持するか、どの設定へ変更するかを判断する。
全体の進行は呼出元が担当し、依頼・run・履歴・stateには[分析先と履歴の共通手順](../analyze/references/history-recording.md)を使う。
このSkillは依頼された範囲の比較と推奨を返し、委任された範囲で採否を判断する。
特徴量の追加・削減・変換が主目的なら `feature-design` を使う。

## 入力と判断基準

既存の依頼・コード・結果から次を揃え、判断に必要な未決事項を確認する。

- 学習・予測手順と基準パラメータ、変更する設定と固定条件。
- データの版・対象・分割規則、train・valid・pretest・testの利用可能な区分と利用履歴。
- 主指標の定義・方向・集約方法、必要な改善幅、副指標や費用の制約。
- 探索方法・パラメータ範囲・候補値・乱数、試行数や時間の上限、選定の委任範囲。

実行前に[共通のデータ利用方針](../modeling/references/data-usage.md)を読み、呼出元から今回の利用範囲と履歴を引き継ぐ。

## 手順

1. **比較条件を揃える。** [評価設計](references/evaluation.md)から用途に合う分割と指標を選ぶ。
   基準と候補には同じ評価対象・分割・集約方法を使い、前処理は各学習部分で学習する。
2. **基準を診断する。** trainで学習し、学習側と利用できるvalid・pretestの性能と符号付き差を確認する。
   用途に必要な性能と、学習時からの低下を分けて捉える。既存の同条件の予測・評価は再利用する。
   ばらつきが判断を左右する場合は[評価の不確実性](references/evaluation-uncertainty.md)から追加診断を選ぶ。
   bootstrapによる分布・区間やKS統計量Dは、確かめたいことと計算負担に応じて使う。
3. **候補を比較する。** 診断から変更意図を定め、計画した候補を学習・評価する。
   2値分類のROC・較正やスコア分布をPythonで描くときは、[inquiry-lab-api](../inquiry-lab-api/SKILL.md)で対応する関数を確認する。
   設定、主指標と基準との差、副指標、費用、失敗を保存する。探索範囲を変えたら根拠となるrunを記す。
4. **次の行動を決める。** 改善幅と制約に照らして候補・現行維持・保留を選ぶ。
   追加試行で判断が変わりそうなら予算内で続ける。委任されていないトレードオフは、差と代償を利用者に示す。

## 終了条件

依頼された比較に答えられた、追加試行の価値が低い、または予算に達したら、推奨・判断と残る証拠不足を返す。
開発比較の依頼は、候補を支持する結果が得られた場合もそこで完了する。
testの評価・再評価を依頼範囲に含む場合は、共通のデータ利用方針の進行条件と固定事項に従う。
区間推定を行う場合は、評価標本の独立性と利用履歴を確認し、評価の不確実性の手順を使う。
期待以下の結果も保存して今回の依頼を閉じ、継続・再開の判断へ利用履歴を引き継ぐ。

## 出力

[レポート雛形](assets/report.md)でrunの `result.md` に比較結果をまとめる。
委任時は割当runを返し、全体の履歴・state・`output.md` は全体進行担当が更新する。
単独実行では担当者が共通記録を更新し、複数runの結果を同じ雛形で `output.md` に統合する。
執筆には[成果物の共通方針](../analyze/references/deliverables.md)を使い、次の5章で変更意図・比較結果・判断をつなぐ。

1. **結論：** 目的、推奨設定・現行維持・保留、決め手、重要な留保を示し、性能と選定理由へリンクする。
   testの評価結果と採用判断は区別する。モデル・前処理・パラメータの版を特定し、主要な変更値は本文、全設定は原本へ置く。
2. **モデルの性能と診断：** 用途に必要な性能水準と学習時からの低下を分けて説明する。
   今回のtest評価・再評価を実施した場合は先に示し、未実施なら理由と過去の利用履歴を記す。
   性能表にはモデル版、分割の役割と対象、指標・単位、点推定、事前基準との関係を載せる。
   区間推定や追加診断を行った場合は、その方法・対象・結果を添える。
   手順2の開発側の診断と用途への懸念を示す。testの評価と、その結果を受けた課題分析を区別し、
   再学習でモデルや区分の役割が変わった結果は分ける。算出不能は理由を添え、評価条件へリンクする。
3. **調整方針と検証：** 入力・期間・集団、使用した区分と分割理由、基準設定、探索方法・範囲・選定理由・予算、
   判断基準と判断者、前処理の学習範囲・乱数・区間の算出対象を共通条件としてまとめる。
   小節は主要な調整方針ごとに作り、当時の観測・変更意図・選んだ設定と理由・固定条件・検証・判断をつなぐ。
   同じ方針を確かめた複数runは統合する。比較表には設定・モデル版、同条件の主指標と基準との差、副指標・費用、選定基準への適合を載せる。
   当時の動機が記録されていなければ不足とし、後の結果で補わない。条件・基準の変更は理由、既に見た証拠、比較への影響を残す。
   testへ進んだ根拠と固定したモデル・評価方法、または評価せず終了した理由から2章へつなぐ。
4. **適用範囲と残る課題：** 確認済み・未確認の利用条件、証拠不足、利用者に残る判断と結論の見直し条件を示す。
   今回の停止理由と次の分析候補、データ利用履歴と再開に必要な条件を記す。
5. **参考：** 作業履歴、全候補の結果、評価方法・指標の定義への入口をまとめる。

各runから入力・コードの版、設定、分割、乱数、環境、全候補の結果と成果物を辿れるようにする。
探索ツールのtrialは原本に保存し、runは問いと判断のまとまりで記録する。
