# 探索的データ分析（EDA）

対象の特徴を広い視点から捉え、根拠と限界を添えてデータを説明する。
利用意図があれば、それに使えそうな切り口や仮説の芽も探す。具体的な検証仮説や目的変数は必須にしない。
データの形・観測の構造・利用目的に応じて参照を組み合わせる。

## データを説明するとは

何が、どの範囲で記録され、どのような特徴・違い・関係・時間的変化が現れているかを説明する。
読み手が典型的な姿、その多様性、条件による違いと、観測できない範囲を理解できることを目指す。
全体像をつかむ依頼では、次のような視点を広く検討する。

| 視点 | 説明する内容の例 |
|---|---|
| 観測対象・イベントの性質 | 何の記録か、イベントの種類・頻度・規模・継続時間 |
| 分布と構成 | 典型的な値、ばらつき、偏り、少数のケース、全体の内訳 |
| 時間的な傾向 | 増減、周期性、変化点、発生間隔 |
| 集団や条件による違い | 属性・場所・状況ごとの差、全体の平均に隠れる違い |
| 関係と繰り返し | 項目間の関係、同じ対象の反復、イベントの順序や共起 |
| 観測上の制約 | 欠損、収集・抽出の偏り、定義や記録方法が見え方に与える影響 |

この例は切り口に当たりをつける手がかりであり、固定の質問票や全項目の実施要件ではない。
データに存在しない構造を要求せず、列名・比較群・時間粒度・方法は現物に合わせて選ぶ。
利用意図は注目する切り口を加える手がかりにする。全体像の把握では、その意図に直結しない特徴も拾う。
特定の関係や現象を調べる依頼では、既知の全体像を使い、指定範囲の説明を補う。

## 1shotの実行契約

1回の呼び出しで、探索計画、計画した観察、解釈・報告を行って完了する。
1shotは一つのツール呼び出しという意味ではなく、複数の集計・図表・事例確認を含む一つの探索単位である。
結果から生まれた問い・切り口は次の候補として返し、その場で追加探索しない。
自分でEDAを再呼び出したり、子エージェントへ新しい探索を渡し続けたりしない。

依頼整理・実行記録は `analyze` の共通手順を使うが、EDAを選択済みとし、一般の分析ループや統合レポート作成へは進まない。
一回分を一つのrunとして返す。計算上の分割、同じ計画の誤実装・表示不備の修正はできるが、
新しい分析条件を追加する理由にはしない。中断からの再開も、未完了の計画と報告を仕上げる範囲とする。
完了した探索からさらに進む判断は、呼出元または `eda-loop` が担当する。

## 入口で確認する

[依頼と返却の契約](references/request.md)を読み、今回の関心・入力・既知の観測・固定条件と裁量・予算・runの保存先を確認する。
loopや他のエージェントから渡された依頼も、利用者からの直接依頼も同じ契約で扱う。
入力の版・定義・取得経緯と既存のコードから分かる事実を先に調べ、未決のものだけ少数ずつ確認する。

- **目的と関心。** 全体像をつかむのか、既知の現象を掘り下げるのかを依頼から捉える。指定がなければ広いデータ理解を出発点とし、利用意図はあれば受け取る。
- **観測単位と関係。** 1行の意味、キー、対象・期間、値の単位、関連表、同じ対象の反復観測を押さえる。
- **利用範囲。** 読めるデータ・項目・期間、利用目的、出力先を確認する。予測用途では、値を読む前に下記の予測準備を参照する。
- **今回の区切り。** 今回観察する範囲、時間・計算量と総評の時間、判断の委任範囲を定める。

定義不足も調査対象にできるが、単位・意味・収集条件を推測で確定しない。
既存資料を読む段階と、実データを探索する段階を分け、利用範囲が不明なデータの探索は保留する。

## データと目的に合う参照を選ぶ

一つのデータセットを一種類に分類する必要はない。複数の条件に当てはまれば組み合わせる。
選んだ参照と今回使う観点を依頼・計画に残す。各文書の方法は候補であり、全項目の実施を要求しない。

| 条件 | 読む参照 | 主に決めること |
|---|---|---|
| 列と行で観測・属性を扱う | [表形式のデータ](references/tabular.md) | 項目の役割、分布・欠測、関連、比較の分母 |
| イベント、イベント内の参加者、同じ対象の反復観測や時間順序を扱う | [イベントと反復観測](references/events.md) | 観測単位、イベント内外の関係、集約・結合・時間の扱い |
| 将来の予測やモデル作成に使うデータを調べる | [予測モデルの準備](references/prediction.md) | 予測単位と時点、情報の利用可能時点、目的変数、探索・評価の分離 |

たとえば「1行がイベントへの参加記録で、同じ参加者が複数回現れる表」なら表形式とイベントを読む。
将来の結果を予測する準備なら予測準備も加える。記述的な分析には予測の手順を一律に適用しない。
画像・音声など、この参照で扱えない性質が主要な場合は、その分析に必要な観察方法を個別に定める。
新しい見方の恒常的な追加は、今回の分析とは別のSkill改訂として扱う。

## 暫定的な質問を立て、一括で確認・評価する

1. **構造と実例を確認する。** 許可された入力の定義・スキーマ・少量の実例と既知の観測を読み、
   観測単位と値の意味を捉える。この準備で見た範囲も記録し、実例だけから全体の傾向を断定しない。
   ローカルのCSV・TSV・Parquetでは[データの基本確認](references/data-inspection.md)を読み、
   `inquiry-lab data inspect / values` で取得する範囲・欠損定義・表示の省略を揃える。
2. **説明のための質問を列挙する。** 上の視点と選んだ参照から、何を知ると対象を説明できそうかを考える。
   例えば時系列なら「発生頻度は期間を通じて安定しているか」「時期によって構成や規模も変わるか」など。
   質問はデータに合わせて作り、特定の答えや仮説の個数を要求しない。
3. **今回確認する質問と方法を選ぶ。** 説明への貢献、視点の偏り、既調査との重複、費用から選ぶ。
   全列・全組み合わせの網羅は求めない。各質問に、見る理由、対象・比較条件・集約単位・方法を対応づけ、
   質問群と計画、見送った重要な視点と理由をrunに残してから一括観察へ進む。
4. **根拠を添えて回答し、説明への貢献を評価する。** 計画した集計・可視化・事例確認を実施し、
   観測、説明候補、未検証の仮説を分けて読む。質問ごとに回答と根拠、または判断できない理由を残す。
   目立つ差の有無だけでなく、対象の姿をどう説明できるようになったかを整理する。
5. **質問群を振り返る。** 回答できた質問だけで全体像を十分説明できるか、重要な視点に抜けがないかを評価する。
   質問は暫定的なものとして扱い、観察で判明した前提違い、修正・追加すべき質問とその理由を返す。
   新しい条件・手法での確認は今回実行せず、呼出元または `eda-loop` が次のrunを判断する。

取得・抽出方法が不明なら標本内の記述として扱う。重要な質問を見送った理由や、実施できなかった項目も報告する。
質問の変更案と当初の計画を区別し、結果に合わせた仮説を事前仮説として書かない。

重要な観測には件数・分母・単位・比較条件を添え、別の説明や反例も検討する。
元データを保ち、除外・補完・変換を試す場合は理由、対象件数、処理前後の結論への影響を残す。
探索で見つけた関連は標本と条件の範囲で解釈し、原因やモデル改善効果と同一視しない。
検定・区間推定は問いに必要な場合だけ選び、依存関係と探索で比較を重ねた影響を考慮する。
確証や因果の判断が必要なら、必要な独立データ・検証設計を次の分析として示す。

## 判断基準と区切り方

成果は、対象の典型・多様性・関係や変化を根拠とともに説明でき、説明の不足と限界が分かるかで評価する。
指定範囲の探索ではその範囲に合わせる。図表数・仮説数や、当初の質問にすべて答えたことだけを十分条件にしない。
「明瞭な傾向を確認できなかった」も結果とし、未調査・件数不足・計算不能とは区別する。
品質の合否は既存仕様や合意した基準で判断する。基準がなければ観測値と利用への影響を示し、合否を未定とする。
概観後に初めて基準を設ける場合は、既に見た証拠と理由を残し、事前基準による検証とは区別する。

合意した関心・データ・予算の範囲では、エージェントが今回の見方と方法を選ぶ。目的・対象・予算の拡大、
未定の品質基準、品質と対象数のトレードオフは、証拠・影響・選択肢を利用者に提示し、依存する行動を保留する。
業務上の重要性が不明な順位、新たな収集や施策の実施も利用者に委ねる。

計画した各項目について観測・解釈または未実施・評価不能の理由を整理し、run結果を返したら完了する。
仮説や目立つ傾向が得られなくても終了する。予算に達した場合や前提が成立しない場合も、
確認できた範囲、未完了の項目、再開に必要な条件を示して今回を閉じる。

## runを返す

[依頼と返却の契約](references/request.md)と[run結果雛形](assets/result.md)に従い、指定runの `result.md` と成果物を返す。
新規runの準備には依頼契約に記したCLIの `--template eda` を使う。準備済みのrunはそのまま使う。
本文は観察の位置づけから方法・結果・解釈と限界・再現情報へ進む5章とし、今回の根拠を確認できるようにする。
質問別の回答・実施状況や次の候補は付録の作業記録へ置く。
直接呼ばれた場合も出力はrunとし、`output.md` は執筆・更新しない。
複数runの統合、次のEDA、仮説の検証、機械学習への反映は呼出元が担当する。
EDAの知見だけでモデル変更の効果を断定しない。

考え方の参考：[NISTのEDA概説](https://www.itl.nist.gov/div898/handbook/eda/section1/eda11.htm)。
このSkillの参照構成・判断者・停止条件は、inquiry-labでの利用のために定める。
