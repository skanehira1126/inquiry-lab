# モデル開発のデータ利用

モデルの構築・改善、予測用途のEDA、モデルの比較・診断で、データを使う前に読む。
全体進行担当が利用範囲・履歴と今回の目的を専門Skillへ渡し、testの評価・再評価へ進む判断を行う。
専門Skillは依頼された範囲の結果を返す。単独実行ではその担当者が依頼範囲内の判断を担う。

## データの役割を決める

| 名称 | 役割 |
|---|---|
| train | モデル・前処理の学習 |
| valid | 特徴量・パラメータの調整と比較 |
| pretest | 開発上の意思決定を検証し、testへ進む根拠に使う擬似ホールドアウト |
| test | 最終ホールドアウト。開発側で裏付けた構成の評価、弱点の発見、改善後の確認 |

testの要否はユーザーの指定に従い、指定がなければ目的とデータ条件から判断する。
必要なら開発開始前にtestを確保し、残りを開発データとして扱う。既存案件では版・分割・利用履歴を引き継ぐ。
データ量と時間・対象間の依存に応じて区分を設け、常に4分割することは要求しない。
pretestを確保できなければ、開発側のどの検証で判断を裏付けるかと不足を残す。testがなければ開発結果として報告する。
既存データの呼称はこの役割へ対応づけ、名称だけで未使用・独立と判断しない。
具体的な分割・比較方法は[評価設計](../../parameter-tuning/references/evaluation.md)で選ぶ。

## 開発・診断に使う

train・valid・pretestでは、EDA、特徴量設計、設定比較、診断を反復できる。
評価への適応リスクを許容し、多重評価を理由に探索を一律に制限したり、試行ごとに未使用データを要求したりしない。
ただし、選定に使った成績を独立した性能評価とは扱わない。予測時点の情報利用を守り、前処理は各学習部分で学習する。

診断は目的に合う区分と予測を選び、学習標本内の理解と学習外の評価を区別する。
OOF予測を使う場合も、対象行と各モデルの学習範囲を対応づける。
testの正解・性能は最初の評価まで改善判断に使わない。評価後は誤差分析やEDAで課題を調べ、改善仮説へつなげられる。
変更の検証は開発側で行い、testの正解は再学習へ取り込まない。

## testへ進む条件

初回・再評価とも、開発側で「今回の構成・変更を支持する根拠があり、事前に決めた重大な懸念・許容低下に抵触していない」
と判断できるまでtestの評価へ進まない。必要な性能、比較対象、懸念・許容差は候補の結果を見る前に定める。
使えるtrain・valid・pretestの性能と振る舞いを照合し、問いに応じた条件別比較や安定性の確認で裏付ける。
成績差が小さいことだけで過学習の不在を証明したとはしない。基準を変更した場合は理由と既に見た証拠を残す。

開発側に該当例がなく改善を検証できないことも結果とする。関連条件や妥当なストレステストを使う場合は、
何を裏付けられ、何が未確認かを区別する。根拠不足なら保留し、該当例がないことを問題なしの証拠にしない。

testの評価前に、開発データとtestの入力を使うアドバーザリアルバリデーション（AV）で特徴量の懸念を確認する。
予測対象の正解と出所を直接示す管理用の列は使わず、AV自身の検証性能・重要度・分布差をモデルの入力依存と照合する。
AUCの低さを合格条件にせず、懸念への対応と未確認事項を整理する。対象・特徴量が同じなら既存のAV結果を再利用できる。
AVを実施できなければ理由と未確認事項を残す。利用条件や検証の不足で進行条件を判断できない場合は保留する。

進む前に根拠・残る懸念・評価目的を記録し、候補と比較基準、特徴量生成・前処理・モデル設定・予測閾値、
再学習範囲と評価方法を固定する。再学習でvalid・pretestを含めた場合、そのモデルの学習外評価には使わない。

## testから次の改善へ戻す

testで見つけた弱点は開発側の改善へ戻し、再評価にも上の条件を適用する。
採否には、狙った弱点の改善に加え、別の苦手領域が生じていないか、既存の苦手が悪化していないかを含める。
変更前後を同じ対象で比べ、改善と悪化の相殺を全体指標だけで判断しない。具体的な確認は
[誤差分析](../../error-analysis/SKILL.md)と[診断方法](../../error-analysis/references/diagnostics.md#変更前後の誤りを比べる)を使う。

有限のデータでtestを再利用するリスクは許容する。開発側の裏付けを得ても、testへの適応が解消したとは扱わない。
利用履歴は入力分布の参照と正解・性能の参照を分け、各評価前の判断と期待以下を含む全結果を保存する。
報告では開発結果とtest結果、初回評価と再評価を区別し、再利用後の成績を未使用データによる独立評価として示さない。
