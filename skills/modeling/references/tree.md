# modeling の仮説と調査を引き継ぐ

全体進行担当は改善目的を Core に置き、比較したい仮説を枝として登録する。開始・更新・再開には
[共通の tree 手順](../../analyze/references/tree.md)を使う。評価条件・予算・データ利用範囲は依頼に残し、担当仮説に適用する制約を登録する。

委任時は tree の絶対パス、担当仮説 ID、依頼、割当 run、入力の版・比較基準を渡す。同じ仮説の調査を分担する場合は担当する調査 ID も渡す。
各作業者は自分の state のパスを依頼または割当 run に残し、任された範囲を更新する。
設定、採用中モデルと比較対象、予測、実行 ID、指標と利用したデータ区分を run に保存し、
調査の結果と参照先から確認できるようにする。返却を受けた全体進行担当は、原本で評価条件と実測を照合し、
採否の判断とその経緯を履歴に記録する。採用したモデルや現在の性能を支える知見は、根拠のノード ID とともに Core に反映する。

再開時や compaction 後は、`state show STATE` で目的・担当仮説・直下の調査結果を読み直す。
調査の参照先から比較対象と実測をたどり、Core と履歴で採用中のモデルと根拠を確認する。
依頼の上限と消費分から残り予算を確認し、実行中の処理は run の実行 ID やログで稼働状況を確かめる。
test 評価・再評価の前には[データ利用方針](data-usage.md)と利用履歴を照合する。時間上限に達した場合は、
残る問いを仮説・調査に、全体の打ち切りを Core の `stopped` に記録する。
