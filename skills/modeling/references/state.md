# modelingの状態管理

[共通state](../../analyze/references/state.md)のschema version 1とCLIをそのまま使う。
全体の進行担当が一つの`current_task`を管理し、結果を確認してから次の個別作業へ進む。
一度に複数の作業を子へ委任しない。複数候補の比較は、一つの作業内で順に実施できる。

## 保存する内容

| 項目 | modelingでの内容 |
|---|---|
| `goal`・`completion_criteria` | 改善目的と全体の終了条件。今回の診断・実験の完了とは分ける |
| `current_conclusion` | 現在採用しているモデルと、性能・性格・探索全体の見立ての要約。未採用ならその旨 |
| `current_task` | 今回の問い、結果確認まで含む`done_when`、状態、割当run、実施済み・未実施の進捗 |
| `next_action` | 次の具体的な行動と理由。委任中は結果待ち・確認など |
| `constraints`・`blockers` | 今回の終了時刻または残り時間・計算予算、固定する評価条件、データ利用制約、実行や判断を妨げる未決事項 |
| `references` | 依頼、採用中モデル、比較基準、今回の候補、最新の性格把握、データ利用履歴、実行情報への参照 |
| `history_sequence` | 全体進行担当がstateへ反映済みの最後の履歴番号 |

モデル・設定・データ・コードの版、評価結果、採否の理由はrunと原本に保存する。
見立ての根拠・残る仮説や候補も履歴・runに残し、stateから辿れるようにする。
全体目標が未達のまま時間・予算で区切る場合は`status: stopped`とし、未達条件と再開時の次の行動を残す。
`references`のlabelで各参照の役割を示し、実在する対象だけを載せる。採用中モデルと比較基準が同じなら、その旨をlabelに示せる。
新しい候補の学習や良い数値だけで採用中モデルを置き換えず、採用判断を履歴へ残してから更新する。
実行中の処理は、実行先・実行ID・ログ・出力先・確認方法をrunに残し、stateから辿れるようにする。

## 個別作業と委任

1. **着手前に保存する。** 全体進行担当がrunを用意し、問い・完了条件・比較基準・固定条件・裁量・予算を依頼に記す。
   `current_task`と依頼への参照を保存してから実行する。既存の未完了runを再開する場合は同じ保存先を使う。
2. **必要なら一件を子へ渡す。** 使用Skill、依頼、必要な既知の結果と根拠、入力の版と利用条件、割当runを渡す。
   子は今回の作業結果・成果物・完了状況・未確認事項をrunへ保存して返す。全体state・共有履歴・`output.md`は全体進行担当が更新する。
   委任先と返却先は依頼・runに残す。子の会話だけに進捗や結果を残さない。
3. **返却を確認して反映する。** 完了条件と原本を照合し、未実施・失敗・結果待ちを区別する。
   全体進行担当が結果と判断を履歴へ記録し、現在の理解、必要な採否、終了条件、次の行動をstateへ反映する。
   子の終了通知だけで作業を完了扱いにしない。修正が必要なら同じ作業を続け、新しい問いは次の作業にする。

## 別チャットで再開する

同じ分析先へのアクセスとその絶対パス、使用するmodelingの参照先を引き継ぐ。
全体進行を交代する場合は旧担当のstate更新を止め、新担当一人が更新を引き受ける。

復元は[共通stateの更新と再開](../../analyze/references/state.md#更新と再開)に従う。
採用中のモデル、現在の見立て、今回の対象、完了済みの範囲、データ利用履歴、残り予算、次の判断を復元する。
前回の時間上限を過ぎている場合は、再開指示から今回使える時間を確認して更新する。
子の会話に再接続できない場合も、保存済みrunの実行情報から確認する。状況が不明なら確認待ちとしてstateに残す。

schemaは担当者の排他や実行状態を自動管理しない。担当の交代と実行状況の照合は、全体進行担当の手順として行う。
