# 作業historyの記入例

以下は架空の独立した3案件のrun本文の抜粋。手順と入力版も架空の例であり、
結果から例示用の[集計CSV](observations.csv)の行を辿れる。run名は案件内のラベルである。
評価への進行判断は[共通のデータ利用方針](../../skills/modeling/references/data-usage.md)に従い、ここでは履歴の記入箇所を抜粋する。

- A：分類モデルの木の深さを比較し、選んだ候補をtestで評価した案件。
- B：別の分類案件で候補を見送り、testを未使用とした案件。
- C：東西店舗の客単価比較に先立ち、欠測の偏りを確認した案件。

## A-dev

Aのrun-001

- **仮説**　木の深さを4から6にすると、新規顧客のvalid AUCは0.02以上改善する。
- **検証**
  - 顧客データv1の開発範囲を顧客単位で固定分割し、深さ4と6を同じ学習手順で比較した。
  - 性能のばらつきを調べるため、予測を顧客単位で再抽出した（2,000回、seed 42）。
- **結果**　valid AUCは深さ4で0.72、深さ6で0.75だった。差は+0.03だった。
- **考察**　必要改善幅+0.02を超えたため、深さ6を候補とする。testへ進む判断には、開発側の残る懸念とAVの確認結果も揃える。
- **参考**　[設定別のAUCと診断値（集計CSVのA-dev行）](observations.csv)

## A-test

Aのrun-002

- **仮説**　固定した深さ6の候補は、独立した顧客で評価してもAUCが0.74以上になる。
- **検証**　testへの進行判断の記録に従い、学習済みモデル・評価方法・点推定の下限0.74を固定した。
  顧客データv1の予約済み顧客で評価し、顧客単位bootstrap（2,000回、seed 42）の百分位区間を算出した。
- **結果**　AUCは0.76、95%区間は0.72–0.80だった。
- **考察**　点推定は事前基準を満たした。区間が下限をまたぐことをレポートに残し、依頼された評価を終えて報告した。
- **参考**　[testのAUCと区間（集計CSVのA-test行）](observations.csv)

## B-dev

Bのrun-001

- **仮説**　木の深さを4から6にすると、valid AUCは0.02以上改善する。
- **検証**　顧客データv2の開発範囲を顧客単位で固定分割し、深さ4と6を同じ手順で評価した。各設定の予測を顧客単位で再抽出した（2,000回、seed 42）。
- **結果**
  - valid AUCは0.72から0.73へ上がった（差は+0.01）。
  - train AUCとvalid AUCの差は+0.06から+0.10へ広がった。
- **考察**　必要改善幅に届かず、候補を見送った。予定した2設定の比較を終え、testは未使用のまま終了した。
- **参考**　[基準と候補の比較（集計CSVのB-dev行）](observations.csv)

## C-count

Cのrun-001

- **仮説**　購入額が記録された取引だけで東西の客単価を比べてよいか判断したい。片方の店舗で欠測が多ければ比較に影響しうるので、まず店舗別の欠測率を確かめる。
- **検証**　4月取引台帳v1を1取引1行として店舗別に集計し、購入額が空の件数を全取引件数で割った。
- **結果**　欠測率は東店2%（100件中2件）、西店20%（80件中16件）だった。
- **考察**　西店の欠測原因と欠測分の購入額を確認できず、客単価の比較を保留した。西店の原票が得られたら再開する。
- **参考**　[店舗別の欠測件数と取引件数（集計CSVのC-count行）](observations.csv)
