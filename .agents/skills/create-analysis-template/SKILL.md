# 分析テンプレートを作る

分析テンプレートは、同じ種類の案件で繰り返し使うテーマ別スキルである。
たとえばモデル評価では、比較方法や禁止するデータ利用をテンプレートで定め、
許容できる誤差など案件ごとに変わる値は、分析開始時の質問として残す。

## 適用条件を決める

依頼や既存の試行から「何を判断するための分析か」「どんな入力があると使えるか」を整理する。
`skills/` に同じ目的のスキルがあれば、適用条件と出力を比較して改訂先を選ぶ。
特徴量選択、モデル改善、チューニング、モデル評価、EDAなどの名称は手掛かりに使い、
実際の問いと必要な証拠に合わせて範囲を定める。

## 評価基準と判断者を詰める

資料や既存コードから分かることは先に調べる。残る選択のうち、後の判断の前提になるものから、
推奨案と理由を添えて少数ずつ利用者に尋ねる。特に次の点を明らかにする。

- **評価基準**　何を何と比較し、どのデータと手順で判定するか。可能なら指標・単位・閾値・その根拠を定める。
  閾値が案件ごとに変わる場合は、誰がいつ決めるかを書く。定量化が難しい場合は、判断材料となる観測を示す。
- **判断者**　基準ごとに、エージェントが判断できる範囲と、利用者が自分で判断したい点を区別する。
  利用者に委ねる判断には、提示する証拠、尋ねるタイミング、回答が得られるまで保留する行動を対応づける。
- **制限・禁止事項**　使えるデータ、手法、時間・計算量の上限と、禁止する操作を明記する。
  禁止事項に抵触する試行は除き、残る方法で問いに答えられるかを判断する。

たとえばモデル改善であれば、「同一の検証データで基準モデルとの差を計算する」はエージェントに任せられる。
「推論時間の増加を許容して採用するか」を利用者が判断したい場合は、両モデルの精度差と推論時間を提示する。
採用判断を委ねられるかどうかは、テンプレート作成時の対話で確かめる。

## テーマ別スキルを作成する

新規作成先は `skills/<テーマ名>/SKILL.md`。ディレクトリと同じ名前を `name` に指定し、
`description` には目的と適用条件を書く。本文に適用時の質問、評価基準と判断者、制限・禁止事項を置く。
案件固有の値は質問として残し、試行の進行と総評は `analysis-framework` の手順に従う。

繰り返す計算や検証にコードが有用なら、テーマの `scripts/` に同梱する。スキル本文から
スクリプトを相対パスで参照し、用途、入力、出力、必要な依存関係、実行例を示す。
作業ディレクトリに依存しないよう、スクリプトの場所はスキルのディレクトリを基準に解決する。
追加・変更したスクリプトは小さな入力で実行し、実際の出力を期待値と照合する。

最後に、想定案件を一つ当てはめて、適用可否、最初の問い、評価に必要な証拠、誰がどう判定するか、
制限に抵触した場合の扱いが読み取れることを確認する。作成先と検証結果を報告する。
