# 分析用Skillを作る

分析テーマごとに `skills/<テーマ名>/` へ独立したSkillを置く。
分析の進行は `analyze`、モデルの構築・改善は `modeling`、固有の方法と依頼の完了条件は各専門Skillが持つ。
依頼・run・履歴・state・レポートの共通手順は `analyze` を参照する。

## 範囲を決める

[analyzeの選択表](../../../skills/analyze/SKILL.md)、[modeling](../../../skills/modeling/SKILL.md)と近いSkillを読み、
何を判断する分析か、必要な入力、結果の使い方を比較する。同じ目的なら既存Skillを改訂する。
一括診断か反復探索かを明確にし、成功時だけでなく、根拠不足や予算到達時に何を返すか決める。
EDAの見方の追加は `eda` の参照文書を改訂する。

## 判断基準を整える

資料とコードから分かることを確認し、分析の選択を変える未決事項だけ利用者に尋ねる。

- **比較と判定：** 何を何と、どのデータ・指標・手順で比べるか。閾値が案件ごとに変わるなら、適用時に決める項目として残す。
- **探索範囲：** 変えるもの、固定するもの、使える入力、時間・計算量の上限。
- **判断者：** 委任された基準でエージェントが決める範囲と、利用者に残る選択。後者は提示する証拠と判断のタイミングを記す。
- **終了：** 問いに答えた場合、候補見送り、証拠不足、予算到達、最終評価後の扱い。

## Skillと雛形を書く

`SKILL.md` は「入力と判断基準」「手順」「終了条件」「出力」を基本に、短く一貫した流れにする。
冒頭に目的、全体進行担当との分担、近いSkillとの使い分けを示す。
共通の記録手順は複製せず、条件付きの詳しい方法は `references/` に置いて読む場面を示す。
注意事項は判断を変えるものに絞り、同じ制約を各節で繰り返さない。

モデル関連Skillでは開発データと最終ホールドアウトの境界・利用履歴を入力に含め、
[modelingのデータ利用方針](../../../skills/modeling/SKILL.md#データの利用方針)を参照する。
依頼された比較・診断の完了と全体の終了を分け、最終評価・再評価の判断は全体進行担当へ返す。
診断のみのSkillでは、一括で確認する範囲と、次の分析へ返す問いを分ける。

`assets/report.md` にレポート雛形を作り、Skillの「出力」からリンクする。
[成果物の共通方針](../../../skills/analyze/references/deliverables.md)を使い、
結論から主要な判断・証拠・前提を辿れる構成にする。
委任時は割当runを返し、共有履歴・state・統合レポートは全体進行担当が更新する。
単独実行時にrunだけを返すか、統合レポートまで作るかはSkillの目的に合わせて明記する。

- 大章の役割と順序をテーマ内で揃え、小見出しは案件に合わせる。
- 変更意図、比較結果、判断と重要な反証を本文へ残す。全試行・全件結果はrunと原本へつなぐ。
- 未実施や保留は理由を記せるようにし、条件付きの項目は必要な場合に使う。
- 入力・コードの版、手順、設定、環境、保存した出力を各runから確認できるようにする。

繰り返す計算を同梱する必要があれば `scripts/` に置き、用途・入力・出力・依存関係を示して小さな入力で動作確認する。

## 呼出元へ登録して確認する

分析の自動選択の入口は `analyze` と `modeling` とし、専門Skillの
`agents/openai.yaml` は `policy.allow_implicit_invocation: false` にする。
実装用の `inquiry-lab-api` は自動選択を有効にする。
専門Skillを追加する場合は、担当する入口へ使う場面・入力・リンク・出力を追加する。
データやモデルの理解・診断はanalyze、モデルの構築・設定比較・特徴量設計はmodelingから参照する。
READMEとAGENTS.mdの構成説明も更新する。

代表的な案件を当てはめ、入力から最初の試行、次の判断、終了、レポートまで辿れるか確認する。
モデル改善では候補見送りと最終評価が期待以下の場合、一括診断では傾向なしと計測不能の場合も確認する。
最後にSkillの構文、自動選択の設定、参照先、雛形との整合性を検証し、変更点と結果を報告する。
